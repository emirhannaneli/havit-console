# Havit KB884L Gaming Keyboard — USB HID Protocol Specification

> **Target Hardware:** Havit KB884L RGB Mechanical Gaming Keyboard (OEM: Rongyuan / HFD `RKGK890`)  
> **USB Identifiers:** `VID: 0x05AC`, `PID: 0x024F`, Release: `0x0120`  
> **Reverse Engineered From:** `DeviceDriver.exe` (1.8 MB x86 MFC C++), `mui.dll`, `device.xml`, `KeyboardLayout.xml`  
> **Toolchain Evidence:** Ghidra 12.1.4 decompiler output via `morluto/rea` (Functions: `FUN_00456c70`, `FUN_004585f0`, `FUN_00457020`, `0x423640`, `0x437980`, `0x42d130`, `0x42d2e0`, `0x42d800`, `0x436980`, `0x416840`, `0x42f840`).

---

## 1. USB Architecture & Interfaces

The keyboard registers multiple USB HID endpoints under `VID_05AC&PID_024F`:

| Interface | UsagePage | Usage | Report Types & Lengths | Purpose |
|---|---|---|---|---|
| `MI_00` | `0x0001` (Generic Desktop) | `0x0006` (Keyboard) | In: 9 bytes, Out: 2 bytes | Standard boot keyboard HID input & NumLock/CapsLock LEDs |
| `MI_01` | `0x000C`, `0x0001`, `0xFFFF` | Media / Mouse / Vendor | In: 3..16 bytes | Consumer multimedia keys, system power, vendor notifications |
| **`MI_02`** | **`0xFF68` (Vendor)** | **`0x0061`** | **In: 65 bytes, Out: 4097 bytes** | **High-speed bulk channel for 160×96 TFT LCD screen animations & GIF frames** |
| **`MI_03`** | **`0xFF13` (Vendor)** | **`0x0001`** | **Feature: 65 bytes, In: 65, Out: 65** | **Control channel for Lighting, Per-Key RGB, Keymap, Macros, Clock Sync & Settings** |

---

## 2. Command Transaction Lifecycle

Every configuration exchange on `UsagePage 0xFF13` follows a strict transaction framing pattern (`FUN_00456c70`):

1. **Transaction Begin:** Send Feature Report `[0x00, 0x04, 0x18, 0x00, ...]` (65 bytes total).
2. **Subsystem Header:** Send Feature Report `[0x00, 0x04, CMD, ...]` to select target subsystem bank.
3. **Data Payload:** One or more 65-byte Feature reports `[0x00, ...64 bytes payload...]`.
   - The end of the data payload terminates with a 2-byte magic trailer: `0x55, 0xAA` (Little-Endian `0xAA55`).
4. **Transaction End / Commit:** Send Feature Report `[0x00, 0x04, 0x02, 0x00, ...]`.
5. **Flash NVRAM Persistence:** Send Feature Report `[0x00, 0x04, 0xF0, 0x00, ...]` to burn changes to EEPROM.

### Timing & ACKs
- A `Sleep(10)` (10ms) delay is required between successive Feature reports.
- Read ACK status via `IOCTL_HID_GET_FEATURE` (`DeviceIoControl(0xb0192)`) or `HidD_GetFeature`.

## 3. Subsystem Command IDs (`byte[1]` in Report `0x04`)

| Command Code | Subsystem | Purpose |
|---|---|---|
| `0x18` | Transaction | Open / Begin Transaction |
| `0x02` | Transaction | Commit / Close Transaction |
| `0xF0` | NVRAM | Burn Settings to Flash Memory |
| `0x11` | Keymap | Upload custom key bindings (Top & Fn layers) |
| `0x13` | Lighting | Set global lighting effect, speed, brightness, RGB color |
| `0x17` | Settings | Sleep timer, key debounce, Win-key lock, Fn toggle mode |
| `0x19` | Macro | Upload macro event table |
| `0x23` | Per-Key RGB | Upload per-key static RGB lighting array |
| `0x28` | Time Sync | Synchronize onboard real-time clock |
| `0x72` | TFT Screen | Allocate 4KB chunk transfer for LCD screen frames |
| `0xF5` | Query | Query current lighting and keyboard state |

## 4. Subsystem Details

### 4.1 Time Synchronization (`0x437980`)
Synchronizes current system date/time to the keyboard's LCD clock widget:
```rust
// Packet 1: Start
[0x00, 0x04, 0x18, 0x00, ... (65 bytes)]

// Packet 2: Select Clock Bank
[0x00, 0x04, 0x28, 0x00, 0x00, 0x00, 0x00, 0x00, 0x01, 0x00, ... (65 bytes)]

// Packet 3: Date & Time Payload
[
  0x00,                // Report ID = 0x00
  0x04,                // Command Header = 0x04
  slot_id + 1,         // Slot (typically 0x01)
  0x5A,                // Sync Flag = 0x5A
  (year % 2000) as u8, // e.g. 26 for 2026
  month as u8,         // 1..12
  day as u8,           // 1..31
  hour as u8,          // 0..23
  minute as u8,        // 0..59
  second as u8,        // 0..59
  0x00, ...,           // Padded with zeroes
  0x55, 0xAA           // Magic Trailer at bytes 63..64
]

// Packet 4: Commit
[0x00, 0x04, 0x02, 0x00, ... (65 bytes)]
```

### 4.2 160×96 Mini TFT Screen Animation Upload (`0x423640` & `0x457020`)
- **Screen Resolution:** 160 × 96 pixels.
- **Pixel Format:** 16-bit RGB565 (`RRRRR GGGGGG BBBBB`).
- **Frame Data Size:** `160 * 96 * 2 = 30,720 bytes` (`0x7800` bytes).
- **Maximum Frames:** 255 frames.
- **Frame Delay:** 30ms to 500ms (stored in header as `delay_ms / 2`).

#### Header Format (256 bytes = `0x100` bytes):
- `Header[0]`: Total frame count $N$ ($1 \le N \le 255$).
- `Header[1..N]`: Frame delay byte for each frame (`delay_ms / 2`).
- `Header[N+1..255]`: `0xFF` padding.

#### Payload Assembly:
Total transmission size = `256 + N * 30720` bytes.  
Total 4KB chunks $C = \lceil \text{Total Size} / 4096 \rceil$.

#### Transfer Sequence:
1. **Start:** Send `[0x00, 0x04, 0x18, 0x00, ...]` on `0xFF13` (65 bytes).
2. **Allocation:** Send `[0x00, 0x04, 0x72, slot_id, 0x00, 0x00, 0x00, 0x00, (C & 0xFF), (C >> 8), ...]` on `0xFF13` (65 bytes).
3. **Data Chunks:** Send $C$ packets of 4097 bytes on **`UsagePage 0xFF68`** via `WriteFile`:
   `[0x00, ...4096 bytes chunk...]`
   After each write, wait for 4097-byte ACK via `ReadFile`.
4. **Commit:** Send `[0x00, 0x04, 0x02, 0x00, ...]` on `0xFF13` (65 bytes).

### 4.3 RGB Lighting Mode Control (`0x42d130`)
```rust
// Packet 1: Start
[0x00, 0x04, 0x18, 0x00, ...]

// Packet 2: Select Lighting Bank
[0x00, 0x04, 0x13, 0x00, 0x00, 0x00, 0x00, 0x00, 0x01, 0x00, ...]

// Packet 3: Mode Settings
[
  0x00,              // Report ID
  0x04,              // Header
  mode_id,           // 0..21 (Static, Breath, Spectrum, Wave, Ripple, etc.)
  brightness,        // 1..5
  speed,             // 1..5
  direction,         // 0..3 (Left, Right, Top, Bottom)
  r, g, b,           // Custom preset RGB color
  0x00, ...,
  0x55, 0xAA         // Magic Trailer
]

// Packet 4: Commit
[0x00, 0x04, 0x02, 0x00, ...]

// Packet 5: Save Flash
[0x00, 0x04, 0xF0, 0x00, ...]
```

### 4.4 Keyboard Settings (`0x436980`)
- **Sleep Timeout:** `0` (Never sleep), `1` (1 min), `5` (5 min), `30` (30 min).
- **Key Response Debounce:** `1ms`, `2ms`, `8ms`.
- **Game Mode:** Lock Windows key (`WinKey`), lock Alt+Tab / Alt+F4.
- **Fn Layer Switch:** Momentary (hold) vs Toggle (press).
